# gcli "Джикли" v5.5.0 — ИИ-агент в терминале

Агентное приложение для терминала: читает проект, пишет код, запускает
команды и инструменты, ведёт сессию. Один бинарник, без внешних зависимостей
модуля Go (в `go.mod` их нет вообще), конфигурация в `~/.gcli`.

## Установка

Готовые бинарники — в `builds/`, пять платформ. Сверить с `SHA256SUMS.txt`:

```bash
sha256sum -c builds/SHA256SUMS.txt      # Linux
shasum -a 256 -c builds/SHA256SUMS.txt  # macOS
```

Положить бинарник в `PATH` (Linux/macOS — `chmod +x`). Windows: файл
`gcli-5.5.0-windows-amd64.exe` положить в любой каталог из `PATH`.

Из исходников — Go 1.21 или новее:

```bash
git clone https://github.com/gcli-terminal/gcli.git
cd gcli && ./build.sh            # все платформы в builds/
./build.sh one linux amd64       # только своя
```

## Быстрый старт

```bash
gcli -setup        # мастер: провайдер → ключ → модель
gcli               # интерактивный REPL
gcli -p "текст"    # один запрос и выход, для скриптов и CI
```

Ключ можно не вводить в мастере — достаточно переменной окружения
(см. [Провайдеры](#провайдеры-и-модели)). В REPL после баннера видна
строка состояния: модель, режим (`agent` или `chat`), размер контекста,
автопилот и предупреждение об отсутствии ключа.

Ключи ввода прямо в REPL:

| Ввод | Что делает |
|---|---|
| `текст` | запрос к модели |
| `/команда` | команда REPL (см. ниже) |
| `@путь` | приложить файл к запросу |
| `#текст` | записать факт в память проекта (`GCLI.md`) |
| `\` в конце строки | перенос строки |
| `Ctrl+O` | показать или свернуть размышления модели |
| `Ctrl+C` | прервать генерацию |
| `Ctrl+D` | выход |

## Флаги

```
Основное:
  -p <запрос>            один запрос и выход (скрипты, CI)
  -c                     продолжить последнюю сессию
  -r <номер>             возобновить сессию №N (список — /sessions)
  -agent on|off          агентный режим (инструменты), по умолчанию on
  -autopilot on|off      автопилот: одобрять безопасные действия самому
  -autopilot-all on|off  автопилот повышенного риска: одобрять всё
  -yolo                  без подтверждений, кроме опасных команд
  -sandbox on|off        песочница файлов: пути вне рабочего каталога запрещены

Провайдер и модель:
  -provider <id>         zai | openrouter | openai | anthropic | ollama | свой id
  -model <имя>           модель, например glm-4.6 или openai/gpt-4o
  -setup                 мастер настройки
  -subagent on|off       разрешить субагентов

Интерфейс:
  -compact               компактный вывод, меньше пустых строк
  -no-color              без цвета
  -color <уровень>       auto | 16 | 256 | truecolor | none
  -ascii                 только ASCII-псевдографика
  -json                  машиночитаемый вывод: только ответ, без UI
  -v                     версия и платформа
```

`-json` отключает весь UI: удобно для CI и скриптов, которые берут stdout.

## Инструменты агента

Всё, что агент умеет вызывать. Режим `chat` их не видит, режим `agent` —
видит. Список с фильтрами по категории — `/tools`.

### Чтение и запись файлов

| Инструмент | Параметры | Что делает |
|---|---|---|
| `read_file` | `path`, `offset`, `limit`, `escape` | текст файла с номерами строк; `escape` показывает невидимое |
| `write_file` | `path`, `content` | создать или перезаписать; перед записью показывается diff |
| `edit_file` | `path`, `old_string`, `new_string`, `replace_all` | точечная замена; `old_string` должен совпадать дословно |
| `list_dir` | `path`, `depth` | содержимое каталога |
| `glob` | `pattern`, `max_results` | поиск по шаблону с `**` |
| `grep` | `pattern`, `path`, `include`, `max_results` | поиск по регулярному выражению (RE2) |
| `inspect` | `path`, `offset`, `limit`, `search` | файл с видимыми табами, CR, неразрывными пробелами, BOM |

### Выполнение и сеть

| Инструмент | Параметры | Что делает |
|---|---|---|

| `web_fetch` | `url`, `max_chars` | страница как текст |
| `job` | `action`, `command`, `id`, `workdir`, `timeout_sec` | фоновые процессы: `run`, `status`, `output`, `stop`, `clear` |

### Проверка и контроль

| Инструмент | Параметры | Что делает |
|---|---|---|
| `verify` | `command`, `suggest`, `workdir`, `timeout_sec`, `no_baseline` | проверка проекта; без команды определяет по `go.mod`, `package.json`, `Cargo.toml`; показывает только новые падения |
| `project_info` | — | корень проекта, стек, точки входа, команды сборки |

| `todo_write` | `todos` | план многошаговой задачи со статусами |
| `think` | `thought` | приватное размышление, ничего не меняет |
| `task_note` | `title`, `body` | заметка в память задачи: доступна субагентам и в `/export` |
| `remember` | `action`, `fact`, `note` | долговременная память между сессиями |

| `handoff_read` | — | прочитать последний снимок |

| `ask_user` | `question`, `options` | вопрос пользователю; звать редко |
| `ask_trace` | — | что спрашивали у пользователя и что ответили |
| `extend_turns` | `reason`, `n` | продлить лимит итераций хода; обоснование обязательно |

### Субагенты

| Инструмент | Параметры | Что делает |
|---|---|---|
| `spawn_agent` | `type`, `task`, `name`, `model`, `read_only` | один субагент; типы: `explorer`, `reviewer`, `planner`, `coder`, `tester`, `frontend`, `researcher`, `docs`, `general` |
| `spawn_agents` | `agents`, `sequential` | до шести подзадач; у каждой — `depends_on`, без него пачка параллельна |
| `agent_status` | `action`, `name` | что работает, список запусков, итог по имени |
| `load_skill` | `name`, `query`, `args` | полный текст навыка; без `name` подбирает по описанию |

`type` можно не указывать: роль выводится из текста задачи, а в отчёте
помечается, на какой именно субагент работал.

Зависимости внутри пачки:

```
spawn_agents(agents=[
  {name: "карта",  type: "explorer", task: "найди, где авторизация"},
  {name: "правки", type: "coder",    task: "перенеси middleware",
   depends_on: "карта"},
  {name: "ревью",  type: "reviewer", task: "найди баги",
   depends_on: ["карта", "правки"]},
])
```

`depends_on` принимает имя или номер (`#2`), строку или список. Узел
стартует в волне, где разрешены сразу все его предшественники, поэтому
`depends_on: ["карта", "правки"]` — это один узел с двумя входами, а не две
копии ревью. Отчёты предшественников подставляются в задачу. Циклы и
ссылки на себя отклоняются с понятной ошибкой.

Два оговорённых случая, о которых нужно знать заранее:

- **Повторный вопрос не выполняет работу заново.** Одинаковые задачи в одной
  сессии переиспользуют прошлый отчёт (срок жизни попадания — 20 минут) или
  ждут уже идущую такую же работу. В отчёте это помечено прямо, вместе с
  именем субагента-первоисточника: иначе мигнувший ответ выглядел бы как
  честная минутная работа, и на его выводах построили бы план, сделанный до
  последних правок в коде.
- **Отчёт с пустым или оборванным текстом повторяется.** Сбой сети или
  деградация ответа — до двух попыток (`sub_retries`), отмена и нехватка
  прав не повторяются.

| Инструмент | Параметры | Что делает |

### Пакетные вызовы

`multi_read`, `multi_edit`, `multi_grep`, `multi_bash` выполняют N однотипных
операций одним вызовом. `multi_edit` применяет правки к разным файлам
параллельно, две правки одного файла конфликтуют; `atomic` — сначала
проверяются все, и только потом применяются.

## Конфигурация

`~/.gcli/config.json`, тот же формат у всех полей. Флаги переопределяют
значения файла. Поля `unicode` и `animations` — указатели: `null` означает
«определить автоматически», `true`/`false` — зафиксировать.

```json
{
  "provider": "zai",
  "model": "glm-4.6",
  "agent": true,
  "think": "auto",

  "providers": {
    "myapi": {
      "base_url": "https://example.com/v1",
      "api_key": "…",
      "protocol": "openai",
      "custom": true
    }
  },

  "unicode": true,
  "compact": false,
  "show_time": false,
  "animations": true,
  "mascot": true,
  "plan_mode": false,
  "sandbox": false,

  "max_iters": 0,
  "max_iters_abs": 0,
  "turn_extend_max": 0,
  "turn_extend_step": 0,
  "auto_compact": 0,
  "parallel_tools": false,

  "subagents": false,
  "sub_max_depth": 0,
  "sub_max_par": 0,
  "sub_model": "",
  "sub_max_turns": 0,
  "sub_timeout_min": 0,
  "sub_retries": 0,
  "sub_route": false,
  "sub_budget": 0
}
```

Значение `0` у числовых полей означает «взять значение по умолчанию»:
`max_iters` — 40, `sub_max_par` — 3, `sub_max_depth` — 1,
`sub_max_turns` — 12, `sub_timeout_min` — 10, `sub_retries` — 2.

### Продление хода

Лимит итераций — не стена, а ресурс под запрос. Когда работы честно больше,
чем помещается в один ход, агент может вызвать `extend_turns` и объяснить
одной-двумя фразами, что именно осталось и почему не помещается. Без
обоснования продление не выдаётся.

`max_iters_abs` — абсолютный потолок с учётом продлений (по умолчанию 200).
Продление его не поднимает: оно лишь распределяет запас по требованию модели.
`turn_extend_max` — сколько раз за ход можно продлить (8), `turn_extend_step` —
размер одного продления в итерациях (30); модель может попросить меньше, но
не больше.

Продление отклоняется, если последние ходы повторяют одни и те же вызовы
(менее 30 процентов новых) или израсходовано 90 процентов бюджета сессии
(`sub_budget`). Текущее состояние показывают `/iters` и `self_status`.

Пределы: `sub_max_depth` — от 1 до 3, `sub_max_par` — от 1 до 8,
`sub_max_turns` — от 1 до 60, `sub_timeout_min` — от 1 до 60 минут,
`sub_retries` — от 1 до 3. Глубина 1 означает, что субагенты разрешены,
а вложенные субагенты — нет.

`skills_off` — список имён навыков, которые не нужно предлагать модели.

### Модели субагентов

Один и тот же код в роли `explorer` и в роли `coder` обходится в одну цену,
если субагенты едут на одной модели. Карта проекта и раздел README не стоят
цены топовой модели, а правка кода, которую потом проверит компилятор, —
стоит.

`/agents route on` включает выбор модели по роли: простые роли (`explorer`,
`docs`) уезжают на самую дешёвую доступную модель, требовательные (`coder`,
`reviewer`, `tester`, `frontend`) остаются на текущей. Дальше работает потолок
из `/agents budget N`: на 70% и 90% израсходованного понижается всё, включая
требовательные роли — когда деньги заканчиваются, важна работа, которая
вообще успеет. Ходы при этом урезаются, но не ниже четырёх.

Правила, которые стоит знать до включения:

- **выключено по умолчанию** — молча менять модель нельзя, об этом узнают
  по счёту;
- **явно указанная модель не трогается**: ни `model` в аргументе инструмента,
  ни `model` из front matter своего агента;
- **модель понижается, но никогда не повышается**;
- выбирается только модель, реально доступная у провайдера, и только с
  известной ценой — сравнивать не с чем, а догадка стоит денег;
- каждое решение объяснено в одну строку, и объяснение видно в UI запуска, в
  `/agents`, в журнале сессии и в самом отчёте субагента.

`/agents budget N` — ориентир, а не лимит: превышение не запрещает и ничего
не обрывает. `0` или `off` означает «потолок не задан», и тогда решение по
бюджету не принимается вовсе.

### Навыки

Файл `.md` с front matter. В описании — когда навык нужен; поле `when`
работает как триггер. `$ARGUMENTS` подставляет аргументы вызова.

```markdown
---
name: commit-helper
description: Подготовить сообщение коммита по изменениям в git.
when: пользователь просит написать коммит или коммит-сообщение
---

1. Прочитай `git diff`.
2. Сгруппируй изменения по смыслу.
3. Сообщение в стиле Conventional Commits: `тип(область): что сделано`.
```

Встроенных навыков четыре — они доступны всегда, без настройки:
`frontend-dev` (вёрстка, адаптив, доступность, тёмная тема),
`design-review` (иерархия, ритм, контраст по скриншоту),
`frontend-frameworks` (React, Vue, Svelte, Next), `batch-and-delegate`
(пакетные вызовы и делегирование). Пользовательский навык с тем же именем
перекрывает встроенный.

### Субагенты

Встроенные типы: `explorer` (карта кода), `reviewer` (баги и безопасность),
`planner` (план с фактами `файл:строка`), `coder` (реализация), `tester`
(тесты), `frontend` (вёрстка), `researcher` (сеть и документация), `docs`,
`general`.

`explorer`, `reviewer`, `planner` и `researcher` по умолчанию только читают и
не могут менять файлы. Если задаче очевидно нужен исполнитель, роль
понижается до `general` — задача обычно выполнима, и отказ был бы хуже.

Свой агент — файл `.md` в `~/.gcli/agents/` или `./.gcli/agents/`,
имя файла без расширения становится именем агента.

### MCP

Транспорт stdio, JSON-RPC. Инструменты сервера регистрируются как
`mcp__<сервер>__<инструмент>`, вызов идёт методом `tools/call`, таймаут
`timeout_sec` ограничен диапазоном 5–600 секунд. Глобальный
`~/.gcli/mcp.json` считается доверенным, проектный — требует подтверждения
через `/mcp trust <server>`, отпечаток берётся по содержимому файла.

### Расширения

JSON с описанием инструментов, которые добавляются к агенту под своим
префиксом. Каталог — `/ext trust`, без доверия расширение не грузится.

## Безопасность

Четыре независимых механизма. Ничего из них не включено по умолчанию
насильно: каждый включается явно.

**Подтверждения.** Опасные команды и запись файлов спрашивают подтверждение.
`/yolo` снимает вопросы (кроме опасных команд), `-yolo` — то же на старте.
`/autopilot` одобряет безопасные действия сам, `/autopilot all` — всё
включая опасные команды.

**Песочница файлов.** `/sandbox on` или `-sandbox on` ограничивает доступ
файловых инструментов рабочим каталогом; пути наружу запрещены. Без
песочницы модель может прочитать `~/.ssh/id_rsa` или `~/.gcli/config.json` —
это осознанное поведение, а не недосмотр. В песочнице каталоги с секретами
попадают в запрещённые поддеревья (`WithDeny`) даже внутри разрешённого корня.

**SSRF-защита.** `web_fetch` и `web_search` не ходят во внутреннюю сеть:
проверяется и DNS-ответ, и сам адрес. `localhost`, loopback, приватные
подсети и заблокированные домены отбрасываются до запроса.

**Маскирование секретов.** В выводе инструментов и ответах заменяются
значения, похожие на секреты: ключи AWS (`AKIA…`), Google (`AIza…`),
`sk-…`, GitHub (`ghp_`, `github_pat_`), GitLab (`glpat-`), Slack (`xox*`),
`npm_`, Telegram, а также присваивания `token=…`, `api_key: "…"`,
заголовки `Authorization: Bearer …`.

**Доверие к коду проекта.** Навыки, расширения и MCP из репозитория
исполняются только после подтверждения: `/permissions`, `/ext trust`,
`/mcp trust`. В чужих клонах это то, что отличает проект от доверенного.

## Сборка из исходников

```bash
./build.sh          # все платформы + SHA256SUMS.txt
./build.sh test     # go test
./build.sh vet      # go vet
./build.sh fmt      # gofmt -l
./build.sh one linux amd64
./build.sh clean    # убрать бинарники из builds/
```

Windows: `build.cmd` — та же сборка через Git Bash.

`build.sh` сверяет `var Version` в `src/core/core.go` с `GCLI_VERSION`
(по умолчанию 5.5.0) и отказывается собирать, если версии разошлись: в
бинарнике иначе окажутся два разных номера — в имени файла и в
User-Agent.

Проверки перед коммитом:

```bash
cd src
gofmt -l .
go vet ./...
go test -race -count=1 ./...
```

## Что изменилось в 5.5.0

Релиз-исправление: найденные при параллельной работе субагентов гонки данных и
неверная классификация прерванных запусков. Новых инструментов и команд нет —
5.5.0 чинит то, что ломало работу при `spawn_agents` и Ctrl+C.

**Гонка карты прочитанных файлов.** `Base`, `Restrict` и `Merge` копировали
карту прочитанных файлов без блокировки, тогда как `read_file` писал в неё под
`readMu`. Параллельные субагенты, один из которых читал файл, а второй
создавался, давали фатальную ошибку Go `concurrent map iteration and map write`
— процесс падал целиком, без шанса на перехват. Копирование теперь идёт под той
же блокировкой (`tools/registry.go`, `snapshotRead`).

**Счётчик инструментов субагента.** Хук `OnToolStart` вызывается из горутин
параллельных запусков, а обычный счётчик терял часть вызовов, и `go test -race`
ругался на гонку. Заменён на `atomic.Int64` (`agent/subagent.go`).

**Прерванный субагент больше не считается успешным.** `Agent.Run` превращает
`context.Canceled` в `nil`, а субагент при отмене отдаёт частичный отчёт без
ошибки. Из-за этого прерванный запуск попадал в журнал как `done`, и его
выжимка уходила главному агенту как обычный результат — тот опирался на текст,
оборванный на полуслове. Теперь отмена проверяется раньше ошибки и пустого
отчёта, а статус становится `canceled` (`subagents/pool.go`).

**Отменённый отчёт не попадает в кеш.** При отмене до старта субагента `Spawn`
возвращает ошибку сразу, не занимая слот и не оставляя «полуготовый» запуск в
журнале. Прерванный результат не переиспользуется при повторе той же задачи.

**Дублирующиеся имена параллельных запусков.** Номер автоимени считался по
текущему числу запусков, а сам запуск регистрировался позже и под другой
блокировкой. Два параллельных запуска без имени получали одно и то же
`explorer-1`, и `/agents` с `agent_status` различали их только по ID. Счётчик
теперь живёт отдельно (`nameSeq`).

**Тесты.** Добавлены регрессии на каждое исправление: конкурентное копирование
карты, уникальность и последовательность имён, классификация отмены, отмена до
регистрации запуска, отсутствие кеширования отменённого результата и соблюдение
лимита параллельности под нагрузкой.

**Первая публикация.** Репозиторий выложен на GitHub: `github.com/saaae1337/gCLI`.

## Что изменилось в 5.4.0

**Продление хода.** Новый инструмент `extend_turns`. Лимит итераций больше не
стена: когда работы честно больше, чем помещается в один ход, агент может
продлить лимит, объяснив одной-двумя фразами, что осталось и почему не
помещается. Без обоснования продление не выдаётся. Продление отклоняется,
если последние ходы повторяют одни и те же вызовы (менее 30 процентов новых)
или израсходовано 90 процентов бюджета сессии. Абсолютный потолок
(`max_iters_abs`, по умолчанию 200) продление не поднимает — оно лишь
распределяет запас по требованию. За 10 итераций до лимита модель получает
предупреждение. Новая команда `/iters` показывает лимиты и журнал решений.

**Субагенты.** Автовыбор роли по тексту задачи (без `type` роль выводится
из формулировки), контракт отчёта и проверка результата, заземление выводов
на реально прочитанных файлах, кеш повторов и дедупликация одинаковых задач,
DAG-планирование пачки с `depends_on` и волнами, budget-aware маршрутизация
моделей по роли и расходу сессии (`/agents route`, `/agents budget`).

**Сборка.** Кросс-сборка пяти платформ скриптом, `SHA256SUMS.txt`, CI на
Windows, Linux и macOS с проверкой на Go 1.21 и свежей версии.

## Что изменилось в 5.3.0

**Безопасность.** Песочница файлов с корнями и запрещёнными поддеревьями,
SSRF-защита сетевых инструментов (проверка DNS-ответа и адреса),
маскирование секретов в выводе, доверие к коду проекта для навыков,
расширений и MCP.

**Инструменты.** `verify` с определением проверки по файлам проекта и
сравнением с прошлым прогоном, `project_info`, `changes`, `revert_last`,
`inspect`, `dry_run`, фоновые процессы `job`, `handoff` и `handoff_read`,
`self_status`, `ask_trace`, `task_note`, `remember`.

**Пакетный режим.** `multi_read`, `multi_edit`, `multi_grep`, `multi_bash`
одним вызовом вместо N, с живым прогрессом. `spawn_agents` — до шести
параллельных субагентов (зависимости между ними появились в 5.4.0).

**Навыки.** `load_skill` с автоподбором по описанию, `$ARGUMENTS`,
триггеры `when`.

**Интерфейс.** `Ctrl+O` работает и во время хода, и между ходами — во втором
случае показывает размышления последнего завершённого хода вместо ответа
«размышлений пока нет».

**Сборка.** Кросс-сборка пяти платформ скриптом, `SHA256SUMS.txt`, CI на
Windows, Linux и macOS с проверкой на Go 1.21 и свежей версии.
