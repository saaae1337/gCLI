# gcli v5.0.3 — ИИ-агент в терминале, с живым котом

CLI-приложение, где модель не просто отвечает, а **выполняет задачи**: правит файлы,
запускает команды, ищет в интернете, ведёт план работ и делегирует подзадачи
субагентам. Работает с любым провайдером — от Z.ai GLM и OpenRouter до локальной
Ollama. Только стандартная библиотека Go, без внешних зависимостей.

Внутри живёт **Искра** — кот-помощник и талисман агента. Она **всегда на посту**:
сидит над строкой состояния, моргает и засыпает на простое, думает и работает
вместе с ИИ, мурчит от результата и провожает при выходе.

```
  ◆ gcli v5.0.3  ·  ИИ-агент в терминале
  модель glm-4.6  ·  каталог ~/myproject
  ключ задан  ·  агент  ·  автопилот вкл

  /\_/\
 ( ^.^ )
  > ^ <
  ⎿ glm-4.6 · idle · 12k ctx · agent
  ◆ почини тесты
 ( -.- ) thinking...        ← переливается цветом слева направо
```

## Оформление: стиль «УГОЛЬ»

Тема одна — `ember` («УГОЛЬ»), она же стиль по умолчанию: плоская вёрстка
в духе Claude Code со своим примитивом — события отмечаются **ромбом `◆`**,
результат инструмента идёт с **«зубцом» `⎿`**, ошибка — киноварь, акцент — охра
(фирменный цвет не занимает слот «красный», поэтому `git diff` и `ls`
в том же терминале выглядят согласованно).

Старые темы (orbit, claude, classic, nord, matrix, mono) удалены вместе
с командой `/theme`: один стиль — ноль веток в коде. Если в старом
`config.json` осталось `"theme": "orbit"` — значение молча сводится к канону.

```
  ◆ read_file  src/ui/ui.go
    ⎿ 481 строка · 3мс
  ⚡ bash  go test ./...
    ⎿ ✖ FAIL: 2 теста упали · 4.0с · 12 стр.
```

- **Один стиль**: тема одна, переключать нечего; остаются только уровни
  цвета 16 / 256 / truecolor (авто, переопределяется `-color` или `GCLI_COLOR`).
- **ASCII-режим** (`-ascii`, `GCLI_ASCII`): весь стиль, включая Искру,
  получает ASCII-версию — без кракозябр на терминалах без юникода.
- **Анимации отключаются автоматически** в пайпах, `-json`, `NO_COLOR`;
  явно — `GCLI_NO_ANIM=1`.

## Маскот Искра

Кот gcli нарисован по референсу проекта — три строки и девятнадцать состояний.
Она всегда на посту: сидит **над строкой состояния** и реагирует на всё,
что происходит с агентом:

| Ситуация | Состояние | Кадр |
|---|---|---|
| ждёт команду | idle | `( ^.^ )` |
| пользователь печатает | слушает | `( °.° )` |
| модель рассуждает | думает | `( -.- )` + переливающееся `thinking...` |
| идут инструменты | работает | `( >.< )` + переливающееся `working...` |
| задача выполнена | радуется | `( ^ω^ )`, изредка подмигивает `( ^.~ )` |
| что-то сломалось | хандрит | `( x_x )`, на второй ошибке подряд — `( Ò_Ó )` |
| отказ в подтверждении | удивлён | `( °□° )` |
| большой вывод инструмента | ест | `( ~.~ )` |
| режим плана | задумчив | `( -.- )?` + `planning...` |
| долго нет команд | скучает | `( -.- )` |
| совсем долго / выход | спит | `( -.- ) zZ` |

Полный набор состояний — 19: добавляются моргает, доволен `( ^_^ )`,
смущён `( ^//^ )`, плачет `( T_T )`, испуган `( °△° )`, мурлычет `( ^~^ )`.
Посмотреть все разом — `/mascot demo`.

**Перелив**: слово ожидания (`thinking...` / `working...` / `planning...`)
анимировано цветной волной — яркое ядро бежит слева направо, оставляя
тёплый хвост; на терминалах слабее 256 цветов слово печатается статично.

Анимации простоя аккуратны и безопасны: каждый кадр — одна атомарная
перерисовка с сохранением и возвратом курсора, а сама перерисовка возможна
только пока курсор стоит на строке приглашения. Любая печать — ответ модели,
вывод команды, даже пустой Enter — снимает кота с «живого» дежурства до
следующей усадки, поэтому кадры никогда не наезжают на статус, приглашение
или набранный текст. Пустой Enter не пересаживает кота заново: блок
«кот + статус» появляется только там, где выше появился новый вывод.

Управление:

```
/mascot            показать Искру и справку
/mascot on|off     включить/выключить (сохраняется в config.json)
/mascot demo       проиграть все состояния
/mascot say текст  кот произносит реплику
/mascot wave       помахать лапой
```

- Выключить навсегда: `"mascot": false` в `config.json` или `GCLI_MASCOT=0`.
- Маскот не нужен пайпам и CI — там он выключается сам.

## Режим планирования (/plan)

Как Plan Mode в Claude Code: агент сначала **исследует задачу и составляет план**,
не меняя файлы, а реализацию начинает только после одобрения.

```
/plan              переключить режим
/plan on | off     явно включить/выключить
```

- В статусной строке появляется метка `plan`, в баннере — «план».
- В промпт агента добавляются правила: только читающие инструменты
  (read_file, glob, grep, web_search…), план с шагами и рисками,
  реализация — после явного «ок».

## Кастомные slash-команды

Положите Markdown-файл в каталог команд — и он станет командой агента:

```
.gcli/commands/commit.md      →  /commit       (для проекта)
~/.gcli/commands/review.md    →  /review       (лично для вас)
```

```markdown
---
description: закоммитить изменения по правилам проекта
---
Сделай коммит: посмотри git status и diff, сгруппируй изменения,
напиши сообщение в Conventional Commits. $ARGUMENTS
```

- `$ARGUMENTS` заменяется на то, что написано после команды:
  `/commit добавить тесты` подставит «добавить тесты».
- Frontmatter с `description` не обязателен — но именно он виден в `/help`.
- Префиксы области работают как в Claude Code: `/project:commit`, `/user:review`.
- Примеры — в `examples/commands/`.

## Скиллы (навыки агента)

Markdown-файл с front matter — библиотека знаний, которую модель подгружает сама,
когда задача попадает под описание:

```markdown
---
name: commit-helper
description: Помогает писать качественные git-коммиты
---
1. Сначала посмотри git status… (инструкции агенту)
```

- Каталоги: `~/.gcli/skills/*.md` (глобальные) и `./.gcli/skills/*.md` (проектные, приоритетнее)
- **Встроенные навыки** едут с бинарником: `frontend-dev` (современная вёрстка
  с проверкой по скриншотам), `design-review` (дизайн-ревизия глазами),
  `frontend-frameworks` (выбор стека). Свой файл с тем же именем их перекрывает
- Список навыков подмешивается в системный промпт; полный текст модель получает
  инструментом `load_skill` — экономно по токенам
- Команды: `/skills` (список), `/skill <имя>` (показать), `/skill on|off <имя>`,
  `/skill new <имя>` (создать шаблон)
- Готовые примеры — в `examples/skills/`

## Расширения (свои инструменты в JSON)

Добавьте агенту новые инструменты без перекомпиляции — `~/.gcli/extensions/*.json`
или `./.gcli/extensions/*.json`:

```json
{
  "name": "dev-tools",
  "description": "Быстрые инструменты разработки",
  "tools": [
    {
      "name": "git_status",
      "description": "Краткий статус git-репозитория",
      "command": "git status --short --branch",
      "timeout_sec": 20
    }
  ]
}
```

- Аргумент модели приходит в поле `input` и подставляется вместо `{input}`
- Shell-инструменты требуют подтверждения; `no_confirm: true` отключает его осознанно
- Команды: `/ext` (список), `/ext new <имя>` (шаблон), `/ext reload`
- Примеры — в `examples/extensions/`

## Быстрый старт

1. Скачайте бинарник из `builds/` под свою платформу и запустите.
2. В ответ на отсутствие ключа выполните **`/setup`** — мастер:
   провайдер → ключ → модель (список моделей подтягивается с endpoint-а).
3. Печатайте задачу — агент сам выберет инструменты и выполнит её.
   Каждый опасный шаг показывается и подтверждается.

## Полноценная агентная база

- **Инструменты (18 + расширения + MCP)**: `read_file`, `write_file`, `edit_file`,
  `list_dir`, `glob`, `grep`, `bash`, `web_search`, `web_fetch`, `todo_write`,
  `think`, `task_note`, `load_skill`, `spawn_agent`, `agent_status`, `ask_user`,
  `screenshot`, `read_image`
- **Зрение**: `screenshot` снимает страницу через headless Edge/Chrome/Chromium,
  `read_image` показывает файл — картинка прикладывается к контексту модели
  (OpenAI-совместимые image_url и Anthropic image-блоки). После вёрстки агент
  обязан посмотреть на результат своими глазами
- **Субагенты (10 специализаций)**: explorer, reviewer, planner, coder, tester,
  frontend, researcher, docs, general, custom — плюс **свои агенты** из
  `.gcli/agents/*.md` (front matter: name, description, tools, model, read_only).
  Параллельно до 8, глубина до 3 (`/agents`, `/agents types`, `/agents new <имя>`)
- **MCP-серверы**: конфиг `~/.gcli/mcp.json` / `./.gcli/mcp.json` — инструменты
  сервера регистрируются как `mcp__сервер__инструмент` (`/mcp`, `/mcp reload`)
- **Память проекта**: `/init` создаёт `GCLI.md`; глобальная память — `~/.gcli/GCLI.md`
- **@упоминания**: `@путь/к/файлу` приложит содержимое к сообщению
- **Сессии**: автосохранение, `/resume`, `-c`, `-r N`, `/compact`, авто-сжатие,
  `/export` в Markdown (включая размышления)
- **Чекпоинты**: перед каждой правкой — копия файла; `/undo` откатывает
- **Размышления** `/think on|off|auto` — GLM, OpenRouter, OpenAI, Qwen3, Claude, DeepSeek
- **Метрики и цены**: токены, скорость, стоимость по таблице цен (`/usage`)
- **`-p "запрос"`** — один запрос и выход, для скриптов и CI

## Модель безопасности

- **Файлы**: цветной diff перед записью; `y`/`n`/`a` (всегда в этой сессии);
  чекпоинт перед каждой правкой → `/undo`
- **Bash**: команда показывается; `y`/`n`, `a` — всегда эта команда, `A` — все в сессии
- **Опасные команды** (`sudo`, `rm -rf /`, `dd of=/dev/…`, `curl … | sh`…) — только `y`/`n`
- Разрешения привязаны к сессии: `/permissions reset`

## Сборка

Нужен Go 1.21+. Внешних зависимостей нет — только стандартная библиотека.

```bash
cd src

go build -o ../builds/gcli .   # текущая платформа
go test ./...                   # тесты
go vet ./...                    # статический анализ

../build.sh                     # все пять платформ + SHA256SUMS
../build.cmd                    # то же из Windows
```

`build.sh` кросс-компилирует из любой ОС (windows amd64/arm64, linux amd64,
darwin amd64/arm64), проставляет версию в бинарник и пересчитывает `SHA256SUMS.txt`.

## Ограничения

- Веб-поиск использует HTML-разметку DuckDuckGo — при её изменении может
  потребоваться правка регулярных выражений в `hWebSearch`.
- Список `/models` работает с endpoint-ами, отдающими стандартный JSON
  `{"data":[{"id":…}]}`; иначе введите имя модели вручную.
- Подсчёт токенов — приближённый (если провайдер не отдаёт usage в стриме).
- На Windows shell-инструмент по умолчанию использует `cmd /c`; для Unix-команд
  установите Git Bash и задайте `GCLI_SHELL=bash`.
