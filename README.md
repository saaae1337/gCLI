# gcli "Джикли" v6.2.0 — ИИ-агент в терминале и на десктопе

Агентное приложение для терминала: читает проект, пишет код, запускает
команды и инструменты, ведёт сессию. Один бинарник, без внешних зависимостей
модуля Go (в `go.mod` их нет вообще), конфигурация в `~/.gcli`.

## Установка

Готовые бинарники — в `builds/`, пять платформ. Сверить с `SHA256SUMS.txt`:

```bash
sha256sum -c builds/SHA256SUMS.txt      # Linux
shasum -a 256 -c builds/SHA256SUMS.txt  # macOS
```

Положить бинарник в `PATH` (Linux/macOS — `chmod +x`). Windows: файл
`gcli-6.2.0-windows-amd64.exe` положить в любой каталог из `PATH`.

Из исходников — Go 1.21 или новее:

```bash
git clone https://github.com/saaae1337/gCLI.git
cd gcli && ./build.sh            # все платформы в builds/
./build.sh one linux amd64       # только своя
```

## Быстрый старт

```bash
gcli -setup        # мастер: провайдер → ключ → модель
gcli               # интерактивный REPL
gcli -p "текст"    # один запрос и выход, для скриптов и CI
```

Ключ можно не вводить в мастере — достаточно переменной окружения
(см. [Провайдеры](#провайдеры-и-модели)). В REPL после баннера видна
строка состояния: модель, режим (`agent` или `chat`), размер контекста,
автопилот и предупреждение об отсутствии ключа.

Ключи ввода прямо в REPL:

| Ввод | Что делает |
|---|---|
| `текст` | запрос к модели |
| `/команда` | команда REPL (см. ниже) |
| `@путь` | приложить файл к запросу |
| `#текст` | записать факт в память проекта (`GCLI.md`) |
| `\` в конце строки | перенос строки |
| `Ctrl+O` | показать или свернуть размышления модели |
| `Ctrl+C` | прервать генерацию |
| `Ctrl+D` | выход |

## Флаги

```
Основное:
  -p <запрос>            один запрос и выход (скрипты, CI)
  -c                     продолжить последнюю сессию
  -r <номер>             возобновить сессию №N (список — /sessions)
  -agent on|off          агентный режим (инструменты), по умолчанию on
  -autopilot on|off      автопилот: одобрять безопасные действия самому
  -autopilot-all on|off  автопилот повышенного риска: одобрять всё
  -yolo                  без подтверждений, кроме опасных команд
  -sandbox on|off        песочница файлов: пути вне рабочего каталога запрещены
  -snapshots on|off      теневые снимки проекта на каждый ход (откат — /revert)

Провайдер и модель:
  -provider <id>         zai | openrouter | openai | anthropic | ollama | свой id
  -model <имя>           модель, например glm-4.6 или openai/gpt-4o
  -setup                 мастер настройки
  -subagent on|off       разрешить субагентов

Автономный прогон (см. раздел «Автономный прогон»):
  -mission <режим|файл>  long-time | extra-long-time | overnight (или путь к mission.json)
  -objective <цель>      цель прогона одной строкой
  -deadline <срок>       срок прогона: 4h, 90m или число минут
  -budget <бюджет>       потолок: токены, деньги или оба (500000 или 500000,25)

Watch и сервер:
  -watch "<команда>"     слежение за файлами; проверка упала — агент чинит
  -serve <адрес>         HTTP-сервер: 127.0.0.1:8642; API /v1/* + веб-оболочка /ui/
  -ui <адрес>            сервер + встроенная веб-оболочка; браузер открывается сам
  -serve-token <токен>   токен для -serve (без него — случайный, печатается при старте)
  -mcp-serve             gcli как MCP-сервер по stdio (для MCP-хостов)
  -bench <каталог>       self-bench: прогон задач из .gcli/bench и счёт
  -stats                 дашборд расходов по всем сессиям и выход

Интерфейс:
  -compact               компактный вывод, меньше пустых строк
  -no-color              без цвета
  -color <уровень>       auto | 16 | 256 | truecolor | none
  -ascii                 только ASCII-псевдографика
  -json                  машиночитаемый вывод: только ответ, без UI
  -v                     версия и платформа
```

`-json` отключает весь UI: удобно для CI и скриптов, которые берут stdout.

## Инструменты агента

Всё, что агент умеет вызывать. Режим `chat` их не видит, режим `agent` —
видит. Список с фильтрами по категории — `/tools`.

### Чтение и запись файлов

| Инструмент | Параметры | Что делает |
|---|---|---|
| `read_file` | `path`, `offset`, `limit`, `escape` | текст файла с номерами строк; `escape` показывает невидимое |
| `write_file` | `path`, `content` | создать или перезаписать; перед записью показывается diff |
| `edit_file` | `path`, `old_string`, `new_string`, `replace_all` | точечная замена; `old_string` должен совпадать дословно |
| `list_dir` | `path`, `depth` | содержимое каталога |
| `glob` | `pattern`, `max_results` | поиск по шаблону с `**` |
| `grep` | `pattern`, `path`, `include`, `max_results` | поиск по регулярному выражению (RE2) |
| `inspect` | `path`, `offset`, `limit`, `search` | файл с видимыми табами, CR, неразрывными пробелами, BOM |

### Выполнение и сеть

| Инструмент | Параметры | Что делает |
|---|---|---|
| `bash` | `command`, `timeout_sec`, `workdir` | shell-команда; таймаут 5–300 с, по умолчанию 60 |
| `multi_bash` | `commands`, `max_output`, `timeout_sec` | несколько команд параллельно, у каждой свой код возврата |
| `web_search` | `query`, `max_results` | заголовки, ссылки, сниппеты |
| `web_fetch` | `url`, `max_chars` | страница как текст |
| `job` | `action`, `command`, `id`, `workdir`, `timeout_sec` | фоновые процессы: `run`, `status`, `output`, `stop`, `clear` |

### Проверка и контроль

| Инструмент | Параметры | Что делает |
|---|---|---|

| `project_info` | — | корень проекта, стек, точки входа, команды сборки |

| `todo_write` | `todos` | план многошаговой задачи со статусами |
| `think` | `thought` | приватное размышление, ничего не меняет |
| `task_note` | `title`, `body` | заметка в память задачи: доступна субагентам и в `/export` |

| `ask_trace` | — | что спрашивали у пользователя и что ответили |

### Субагенты

| Инструмент | Параметры | Что делает |
|---|---|---|
| `spawn_agent` | `type`, `task`, `name`, `model`, `read_only` | один субагент; типы: `explorer`, `reviewer`, `planner`, `coder`, `tester`, `frontend`, `researcher`, `docs`, `general` |
| `spawn_agents` | `agents`, `sequential` | до шести подзадач; у каждой — `depends_on`, без него пачка параллельна |
| `agent_status` | `action`, `name` | что работает, список запусков, итог по имени |
| `load_skill` | `name`, `query`, `args` | полный текст навыка; без `name` подбирает по описанию |

`type` можно не указывать: роль выводится из текста задачи, а в отчёте
помечается, на какой именно субагент работал.

Зависимости внутри пачки:

```
spawn_agents(agents=[
  {name: "карта",  type: "explorer", task: "найди, где авторизация"},
  {name: "правки", type: "coder",    task: "перенеси middleware",
   depends_on: "карта"},
  {name: "ревью",  type: "reviewer", task: "найди баги",
   depends_on: ["карта", "правки"]},
])
```

`depends_on` принимает имя или номер (`#2`), строку или список. Узел
стартует в волне, где разрешены сразу все его предшественники, поэтому
`depends_on: ["карта", "правки"]` — это один узел с двумя входами, а не две
копии ревью. Отчёты предшественников подставляются в задачу. Циклы и
ссылки на себя отклоняются с понятной ошибкой.

Два оговорённых случая, о которых нужно знать заранее:

- **Повторный вопрос не выполняет работу заново.** Одинаковые задачи в одной
  сессии переиспользуют прошлый отчёт (срок жизни попадания — 20 минут) или
  ждут уже идущую такую же работу. В отчёте это помечено прямо, вместе с
  именем субагента-первоисточника: иначе мигнувший ответ выглядел бы как
  честная минутная работа, и на его выводах построили бы план, сделанный до
  последних правок в коде.
- **Отчёт с пустым или оборванным текстом повторяется.** Сбой сети или
  деградация ответа — до двух попыток (`sub_retries`), отмена и нехватка
  прав не повторяются.

### Language servers

| Инструмент | Параметры | Что делает |
|---|---|---|
| `lsp_diagnostics` | `path` | диагностика language server по файлу: типы, необъявленные переменные, ошибки импортов |
| `lsp_hover` | `path`, `line`, `character` | тип, сигнатура и документация символа |
| `lsp_definition` | `path`, `line`, `character` | где определён символ: `файл:строка:столбец` |

Серверы поднимаются лениво по расширению файла: `gopls`, `typescript-language-server`,
`pyright-langserver`, `rust-analyzer`. После каждого `edit_file`/`write_file` диагностика
приходит к агенту сама — он видит сломанный тип сразу, без гонок со сборкой.
Переопределение — ключ `lsp` в config.json (`{".go": "gopls"}`), выключатель — `lsp_enabled`.
Столбцы пересчитываются между руночным представлением модели и UTF-16 протокола LSP.

### Пакетные вызовы

`multi_read`, `multi_edit`, `multi_grep`, `multi_bash` выполняют N однотипных
операций одним вызовом. `multi_edit` применяет правки к разным файлам
параллельно, две правки одного файла конфликтуют; `atomic` — сначала
проверяются все, и только потом применяются.

## Автономный прогон

Автономный прогон — это работа агента по несколько часов за один промпт
человека: модель сама крутит цикл, сама решает, что делать дальше, и сама
останавливается, когда выполнены критерии приёмки или кончился бюджет.
Обычный ход заканчивается, как только модель перестала звать инструменты;
в прогоне это не конец работы, а повод спросить себя «а критерии
выполнены?» — и продолжить. Такого режима нет ни в одном другом
терминальном агенте: у них цикл крутится лишь до первого «готово».

### Режимы

| Режим | Срок | Потолок итераций | Чекпоинт каждые |
|---|---|---|---|
| `normal` | без срока | без потолка | — |
| `long-time` | 4 часа | 200 | 10 итераций |
| `extra-long-time` | 12 часов | 1500 | 15 итераций |
| `overnight` | 8 часов | 1000 | 5 итераций |

Любое значение из пресета можно переопределить: файлом, флагом или
подкомандой `start`. Режим задаёт умолчания, человек — исключения.

### Как запустить

Одной командой из терминала:

```bash
gcli -mission long-time -objective "починить все падающие тесты в core" \
     -deadline 4h -budget 500000,25
```

Или из REPL:

```
/mission start long-time 2h 500k починить тесты и добить рефакторинг repo.go
/mission status
/mission save
/mission report
/mission stop
```

### mission.json

Файл `.gcli/mission.json` в проекте описывает прогон декларативно — им
удобно фиксировать долгую задачу в репозитории:

```jsonc
{
  // Цель одной строкой: агент видит её в системном промпте весь прогон.
  "objective": "починить все падающие тесты в пакете core",
  "mode": "long-time",
  // Любое поле пресета переопределяется явно заданным.
  "deadline": "4h",
  "token_budget": 500000,
  "cost_budget": 25,
  "max_tool_calls": 5000,
  // Критерии приёмки: единственное, что заменяет «модель сказала готово»
  // на проверяемый факт. Перед остановкой агент обязан пройтись по списку.
  "acceptance": [
    "go test ./core/ проходит",
    "в отчёте перечислен каждый тест и его статус"
  ],
  // Сколько итераций без прогресса считать застоем (0 = 12 по умолчанию).
  "stall_limit": 0
}
```

### Бюджеты, застой, остановка

У прогона три потолка сразу — время, токены, деньги (плюс итерации и вызовы
инструментов), и срабатывает первый из них. `/iters` и `/mission status`
показывают расход по каждому потолку в реальном времени; `self_status`
отдаёт тот же снимок модели — на длинной дистанции она видит, сколько раз
её просили продолжить, было ли возобновление после обрыва и сколько
сохранений сделано.

Если работа встала (много итераций без нового прогресса), прогон не молчит:
модель сразу получает предупреждение о застое и обязана сменить тактику;
остановка — только когда застой перерастёт лимит втрое: одна честно
тяжёлая задача не должна убивать прогон на середине. Остановки различаются
на дисплее и в журнале: «цель выполнена», «вышел срок», «исчерпан бюджет
токенов», «исчерпан бюджет денег», «нет прогресса», «прервано человеком».

### Пережив обрыв

Состояние прогона пишется на диск (`mission_state.json`) каждые N итераций
и на каждом чекпоинте; события идут в append-only журнал
(`mission_journal.log`). Если процесс убили среди ночи — повторный запуск
с теми же флагами подхватывает прогон с последнего сохранения: счётчики
(время, токены, вызовы) складываются, а не обнуляются, а модель получает
заметку «прогон продолжен после обрыва» с тем, что было сделано до него.

### Отчёт по прогону

`/mission report` строит итоговый документ по журналу: цель и режим,
статус (идёт / чем остановился), таблица счётчиков (время, итерации,
вызовы, токены, деньги) и хроника всех событий — старты, чекпоинты,
возобновления, остановки. Файл пишется в `.gcli/mission_report.md`,
чтобы приложить его к задаче или PR; если журнал был оборван, отчёт
честно говорит об этом в первой строке.

## Теневые снимки и откат

На каждый ход gcli коммитит состояние рабочих файлов в отдельный
репозиторий `.gcli/snapshots.git` — проектный `.git` не трогается.
`/snapshots` показывает снимки списком, `/revert <N>` откатывает проект
к любому ходу целиком: включая правки, сделанные bash-командами мимо
чекпоинтов `/undo`, и удаления.

Откат сам откатываем: перед ним текущее состояние фиксируется снимком,
а точка ухода остаётся на ветке `keep/pre-revert-*` и видна в `/snapshots` —
повторный `/revert` возвращает как было. `.gcli/` в снимки не попадает
(состояние агента не воскрешается откатом), как и зависимости с сборками.
Без git в PATH механика тихо отключается: страховка не ломает ход.
Выключатель — `snapshots: false` в config.json или флаг `-snapshots off`.

## LSP-интеграция

См. инструменты в разделе выше. Ключевое поведение: тихая диагностика

## Сервер, MCP и CI

**`gcli -serve 127.0.0.1:8642`** — HTTP+SSE к тому же движку:

| Эндпоинт | Метод | Что делает |
|---|---|---|
| `/v1/status` | GET | версия, модель, миссия, занят ли агент |
| `/v1/message` | POST | ход агента (`{"text": "..."}`); один одновременный ход |
| `/v1/events` | GET | SSE-поток: `delta`, `tool_start`, `tool_done`, `turn_*` |
| `/v1/mission` | GET/POST | статус и запуск прогона |
| `/v1/mission/stop` | POST | остановить прогон |
| `/v1/sessions` | GET | последние сессии |
| `/v1/history` | GET | переписка сессии (текущая или `?session=<id>`) |
| `/ui/` | GET | встроенная веб-оболочка (страница без токена, данные — с токеном) |

Токен обязателен: без `-serve-token` генерируется случайный и печатается
при старте. Пустой host (просто `:8642`) означает `127.0.0.1` — наружу
только осознанным выбором адреса.

**`gcli -mcp-serve`** — тот же бинарник как MCP-сервер (stdio, NDJSON
JSON-RPC). Инструменты наружу: `gcli_prompt` (разовая задача агенту в
изолированном дочернем процессе), `gcli_mission_status`, `gcli_mission_report`.
Подключается к Claude Desktop, Cursor и любому MCP-хосту: gcli сам
становится инструментом в чужих системах.

**GitHub Actions** — готовые workflows в `examples/github/`: ревью PR
агентом (комментарий с разбором диффа) и автономная миссия по кнопке
(работает в отдельной ветке и открывает PR). Нужен секрет `GCLI_API_KEY`.

## Веб-интерфейс и десктоп

**`gcli -ui 127.0.0.1:8642`** — тот же сервер, что у `-serve`, плюс
встроенная графическая оболочка. Страница встроена в бинарник (`go:embed`),
сборочного конвейера нет; браузер открывается сам, токен подставляется в
ссылку. Оболочка говорит с тем же движком, что и терминал: переписка,
стриминг ответа, вызовы инструментов, свёрнутые размышления (аналог
Ctrl+O), список сессий, карточка миссии с остановкой. Стиль — фирменный
«УГОЛЬ»: уголь и охра, маркер события «◆», зубец результата «⎿».

**gCLI Desktop** (`desktop/`) — отдельное приложение для десктопа, как у
OpenCode: один сервер, много клиентов. Electron-окно само поднимает
`gcli -serve`, ждёт готовности и открывает оболочку; умеет и подключаться
к уже работающему серверу (`GCLI_URL` + `GCLI_TOKEN`). Сборка установщиков
(AppImage/deb/dmg/NSIS) — `npm run dist` в каталоге `desktop/`, подробности
в `desktop/README.md`.

Терминал, браузер и окно десктопа при этом видят одну и ту же сессию:
история, миссии и расход общие.

## Сравнение моделей и расходы

`/ab <модель> <промпт>` — один вопрос двум моделям параллельно: блоки
ответов рядом, под каждым время, токены и цена по локальной таблице.
Ответы `/ab` в контекст не попадают: это витрина выбора, не диалог.

`/stats [дней]` и `gcli -stats` — расходы по всем сохранённым сессиям:
сводка, разбивка по дням и моделям. Деньги считаются по локальной таблице
цен; модели без известной цены помечены `?` — там `$0` значит «не знаем»,
а не «бесплатно».

## Self-bench

`gcli -bench` прогоняет задачи из `.gcli/bench/*.json` на самом себе и
печатает счёт. Задача — промпт плюс критерии: файл существует, в файле
есть текст, команда проходит. Каждая задача исполняется в чистом временном
каталоге изолированным дочерним процессом; проверка локальная, модель
не зовётся. Прогон после изменения цикла/промптов/модели показывает,
улучшило ли: `7 из 8 задач` вместо «кажется, стало лучше». Ненулевой
exit-код при провалах — для CI.

Автонавыки (включены по умолчанию, ключ `mission_auto_skill`): после
успешно завершённой миссии gcli сам записывает навык `auto-*` в
`.gcli/skills/` — цель, статус, хроника чекпоинтов, частые инструменты.
Следующий похожий прогон или субагент подхватывает его через `load_skill`:
агент учится на собственной истории.

```json
      "api_key": "…",

  },

  "unicode": true,
  "compact": false,
  "show_time": false,
  "animations": true,
  "mascot": true,
  "plan_mode": false,
  "sandbox": false,

  "max_iters_abs": 0,
  "turn_extend_max": 0,
```

Значение `0` у числовых полей означает «взять значение по умолчанию»:
`max_iters` — 40, `sub_max_par` — 3, `sub_max_depth` — 1,
`sub_max_turns` — 12, `sub_timeout_min` — 10, `sub_retries` — 2.

### Продление хода

Лимит итераций — не стена, а ресурс под запрос. Когда работы честно больше,
чем помещается в один ход, агент может вызвать `extend_turns` и объяснить
одной-двумя фразами, что именно осталось и почему не помещается. Без
обоснования продление не выдаётся.

`max_iters_abs` — абсолютный потолок с учётом продлений (по умолчанию 200).
Продление его не поднимает: оно лишь распределяет запас по требованию модели.
`turn_extend_max` — сколько раз за ход можно продлить (8), `turn_extend_step` —
размер одного продления в итерациях (30); модель может попросить меньше, но
не больше.

Продление отклоняется, если последние ходы повторяют одни и те же вызовы
(менее 30 процентов новых) или израсходовано 90 процентов бюджета сессии
(`sub_budget`). Текущее состояние показывают `/iters` и `self_status`.

Пределы: `sub_max_depth` — от 1 до 3, `sub_max_par` — от 1 до 8,
`sub_max_turns` — от 1 до 60, `sub_timeout_min` — от 1 до 60 минут,
`sub_retries` — от 1 до 3. Глубина 1 означает, что субагенты разрешены,
а вложенные субагенты — нет.

`skills_off` — список имён навыков, которые не нужно предлагать модели.

### Модели субагентов

Один и тот же код в роли `explorer` и в роли `coder` обходится в одну цену,
если субагенты едут на одной модели. Карта проекта и раздел README не стоят
цены топовой модели, а правка кода, которую потом проверит компилятор, —
стоит.

`/agents route on` включает выбор модели по роли: простые роли (`explorer`,
`docs`) уезжают на самую дешёвую доступную модель, требовательные (`coder`,
`reviewer`, `tester`, `frontend`) остаются на текущей. Дальше работает потолок
из `/agents budget N`: на 70% и 90% израсходованного понижается всё, включая
требовательные роли — когда деньги заканчиваются, важна работа, которая
вообще успеет. Ходы при этом урезаются, но не ниже четырёх.

Правила, которые стоит знать до включения:

- **выключено по умолчанию** — молча менять модель нельзя, об этом узнают
  по счёту;
- **явно указанная модель не трогается**: ни `model` в аргументе инструмента,
  ни `model` из front matter своего агента;
- **модель понижается, но никогда не повышается**;
- выбирается только модель, реально доступная у провайдера, и только с
  известной ценой — сравнивать не с чем, а догадка стоит денег;
- каждое решение объяснено в одну строку, и объяснение видно в UI запуска, в
  `/agents`, в журнале сессии и в самом отчёте субагента.

`/agents budget N` — ориентир, а не лимит: превышение не запрещает и ничего
не обрывает. `0` или `off` означает «потолок не задан», и тогда решение по
бюджету не принимается вовсе.

### Навыки

Файл `.md` с front matter. В описании — когда навык нужен; поле `when`
работает как триггер. `$ARGUMENTS` подставляет аргументы вызова.

```markdown
---
name: commit-helper
description: Подготовить сообщение коммита по изменениям в git.
when: пользователь просит написать коммит или коммит-сообщение
---

1. Прочитай `git diff`.
2. Сгруппируй изменения по смыслу.
3. Сообщение в стиле Conventional Commits: `тип(область): что сделано`.
```

Встроенных навыков четыре — они доступны всегда, без настройки:
`frontend-dev` (вёрстка, адаптив, доступность, тёмная тема),
`design-review` (иерархия, ритм, контраст по скриншоту),
`frontend-frameworks` (React, Vue, Svelte, Next), `batch-and-delegate`
(пакетные вызовы и делегирование). Пользовательский навык с тем же именем
перекрывает встроенный.

### Субагенты

Встроенные типы: `explorer` (карта кода), `reviewer` (баги и безопасность),
`planner` (план с фактами `файл:строка`), `coder` (реализация), `tester`
(тесты), `frontend` (вёрстка), `researcher` (сеть и документация), `docs`,
`general`.

`explorer`, `reviewer`, `planner` и `researcher` по умолчанию только читают и
не могут менять файлы. Если задаче очевидно нужен исполнитель, роль
понижается до `general` — задача обычно выполнима, и отказ был бы хуже.

Свой агент — файл `.md` в `~/.gcli/agents/` или `./.gcli/agents/`,
имя файла без расширения становится именем агента.

### MCP

Транспорт stdio, JSON-RPC. Инструменты сервера регистрируются как
`mcp__<сервер>__<инструмент>`, вызов идёт методом `tools/call`, таймаут
`timeout_sec` ограничен диапазоном 5–600 секунд. Глобальный
`~/.gcli/mcp.json` считается доверенным, проектный — требует подтверждения
через `/mcp trust <server>`, отпечаток берётся по содержимому файла.

### Расширения

JSON с описанием инструментов, которые добавляются к агенту под своим
префиксом. Каталог — `/ext trust`, без доверия расширение не грузится.

## Безопасность

Четыре независимых механизма. Ничего из них не включено по умолчанию
насильно: каждый включается явно.

**Подтверждения.** Опасные команды и запись файлов спрашивают подтверждение.
`/yolo` снимает вопросы (кроме опасных команд), `-yolo` — то же на старте.
`/autopilot` одобряет безопасные действия сам, `/autopilot all` — всё
включая опасные команды.

**Песочница файлов.** `/sandbox on` или `-sandbox on` ограничивает доступ
файловых инструментов рабочим каталогом; пути наружу запрещены. Без
песочницы модель может прочитать `~/.ssh/id_rsa` или `~/.gcli/config.json` —
это осознанное поведение, а не недосмотр. В песочнице каталоги с секретами
попадают в запрещённые поддеревья (`WithDeny`) даже внутри разрешённого корня.

**SSRF-защита.** `web_fetch` и `web_search` не ходят во внутреннюю сеть:
проверяется и DNS-ответ, и сам адрес. `localhost`, loopback, приватные
подсети и заблокированные домены отбрасываются до запроса.

**Маскирование секретов.** В выводе инструментов и ответах заменяются
значения, похожие на секреты: ключи AWS (`AKIA…`), Google (`AIza…`),
`sk-…`, GitHub (`ghp_`, `github_pat_`), GitLab (`glpat-`), Slack (`xox*`),
`npm_`, Telegram, а также присваивания `token=…`, `api_key: "…"`,
заголовки `Authorization: Bearer …`.

**Доверие к коду проекта.** Навыки, расширения и MCP из репозитория
исполняются только после подтверждения: `/permissions`, `/ext trust`,
`/mcp trust`. В чужих клонах это то, что отличает проект от доверенного.

## Сборка из исходников

```bash
./build.sh          # все платформы + SHA256SUMS.txt
./build.sh test     # go test
./build.sh vet      # go vet
./build.sh fmt      # gofmt -l
./build.sh one linux amd64
./build.sh clean    # убрать бинарники из builds/
```

Windows: `build.cmd` — та же сборка через Git Bash.

`build.sh` сверяет `var Version` в `src/core/core.go` с `GCLI_VERSION`
(по умолчанию 6.0.0) и отказывается собирать, если версии разошлись: в
бинарнике иначе окажутся два разных номера — в имени файла и в
User-Agent.

Проверки перед коммитом:

```bash
cd src
gofmt -l .
go vet ./...
go test -race -count=1 ./...
```

## Что изменилось в 6.2.0

**Исправления**

- **Ctrl+O наконец работает.** Терминал жил в canonical-режиме, и line
  discipline перехватывал байт 0x0F до приложения (VDISCARD при IEXTEN) —
  нажатие пропадало, а попутно включало отбрасывание вывода. REPL теперь
  переводит stdin в точечный raw: Ctrl+O доходит сразу, Ctrl+S больше не
  замораживает вывод, стрелки не втыкаются в строку мусором. Backspace
  и Ctrl+U обрабатывает сам gcli, Ctrl+C работает как раньше. На Windows
  выключается строчный режим консоли, на Linux/macOS — точечный termios;
  при выводе в пайп всё идёт по-старому.
- **Размышления больше не «склеиваются»**: ход, закончившийся прямо на
  мысли (обрыв по max_tokens, отмена), оставлял поток открытым —
  приглашение приклеивалось к последней мысли, а карточка инструмента
  дописывалась в неё же. Закрытие потока теперь происходит и в конце
  хода, и перед карточкой инструмента.
- **Дубль заголовка «размышления»** при повторном Ctrl+O после сворачивания.
- Ввод: Ctrl+D — честный EOF на пустой строке, Ctrl+U стирает набранное,
  escape-последовательности (стрелки, Home) глотаются в обоих режимах.

**Веб-интерфейс и десктоп**

- **`gcli -ui`** — встроенная в бинарник графическая оболочка поверх
  `-serve`: чат со стримингом, карточки инструментов, размышления,
  сессии, миссии. Без сборки и зависимостей, страница отдаётся из
  `go:embed`, данные закрыты токеном как и весь API.
- **gCLI Desktop** (`desktop/`) — Electron-обёртка: автономный режим
  (сам поднимает сервер) и подключение к существующему; иконка и стиль
  «УГОЛЬ»; конфиг electron-builder для AppImage/deb/dmg/NSIS.
- API: `/v1/history` (переписка сессии), событие `reason` в SSE,
  подробные payload'ы `tool_start`/`tool_done`.

## Что изменилось в 6.1.0

Три направления: догнать OpenCode там, где он был впереди; удобство;
и то, чего нет ни у кого.

**Догнать OpenCode**

- **LSP-интеграция.** Language servers поднимаются лениво по расширению
  файла (gopls, tsserver, pyright, rust-analyzer), диагностика после
  каждого `edit_file`/`write_file` приходит агенту сама — он видит
  сломанный тип сразу, без гонок со сборкой. Инструменты `lsp_diagnostics`,
  `lsp_hover`, `lsp_definition`. Столбцы честно пересчитываются между
  руночного моделью и UTF-16 сервера.
- **`gcli serve`** — HTTP+SSE к тому же движку: ход агента, статус,
  запуск/остановка миссии, поток событий. TUI больше не единственный
  клиент. Токен обязателен, по умолчанию — только 127.0.0.1.
- **Теневые снимки проекта на каждый ход** и `/revert <N>`: откат к любому
  ходу целиком, включая правки bash-командами мимо чекпоинтов. Откат сам
  откатываем; проектный `.git` не трогается.
- **`/fork [N]`** — ветвление сессии от любого сообщения (разрез только
  в безопасных границах: без разрыва пар «вызов инструмента → ответ»).
- **GitHub Actions** — ревью PR и автономные миссии из CI
  (`examples/github/`).

**Удобство**

- **`/ab <модель> <промпт>`** — один вопрос двум моделям параллельно,
  ответы рядом со временем и ценой.
- **`/stats [дней]`** и `gcli -stats` — расходы по всем сессиям: дни,
  модели, деньги; неизвестные цены помечены, а не обнулены.
- **`gcli -watch "<команда>"`** — слежение за файлами: проверка упала —
  агент чинит код (команда — эталон), до 5 починок подряд.
- **`/mission report html`** — самодостаточная HTML-страница отчёта:
  gist, Pages, файлом в письмо.
- Инструментов стало 32 (было 29): счётчик в тестах обновлён.

**Фирменное — перегнать**

- **Цепочки миссий** (`/mission chain add|list|clear|run`): большая цель
  дробится на шаги со своими потолками, итог шага переносится в промпт
  следующего; прогресс переживает перезапуск.
- **Автонавыки**: удачная миссия сама пишет навык в `.gcli/skills/` из
  журнала — только факты, без выдуманных уроков. Следующий прогон
  начинает не с нуля: агент учится на собственной истории.
- **`gcli -mcp-serve`** — gcli как MCP-сервер: `gcli_prompt`,
  `gcli_mission_status`, `gcli_mission_report` наружу для Claude Desktop,
  Cursor и любых MCP-хостов. Прежде gcli только потреблял MCP, теперь
  сам становится инструментом.
- **`gcli -bench`** — self-bench: задачи из `.gcli/bench/*.json`,
  изолированный прогон, локальная проверка, счёт «N из M» с exit-кодом
  для CI. Улучшения агента теперь измеримы.

Всё то же без внешних зависимостей: `go.mod` по-прежнему пуст.

## Что изменилось в 6.0.0

Главное — автономный прогон: gcli теперь умеет работать по несколько часов
за один промпт человека. Режимы `long-time` (4 часа), `extra-long-time`
(12 часов) и `overnight` (8 часов, с частыми чекпоинтами) задают срок,
потолок итераций и частоту сохранений; любой из пресетов переопределяется
вручную. Режимов с такими именами нет ни у одного терминального агента —
это ниша, а не догоняние.

**Что появилось.**

- Движок миссий (`core/mission.go`): задание в `.gcli/mission.json`, три
  бюджета одновременно (время, токены, деньги) плюс итерации и вызовы
  инструментов, критерии приёмки с обязательной проверкой перед
  остановкой, детектор застоя (предупреждение сразу, остановка при
  застое втрое больше лимита) и продолжение работы после «готово» —
  модель просит продолжить, пока не исчерпан потолок попыток.
- Crash-safe журнал (`core/journal.go`): append-only файл событий с
  контрольными суммами; состояние прогона пишется каждые N итераций,
  после падения процесса прогон подхватывается с последнего сохранения,
  а счётчики складываются, а не обнуляются.
- Команда `/mission` (start, stop, status, save, report) и флаги
  `-mission`, `-objective`, `-deadline`, `-budget` — один и тот же разбор
  аргументов, чтобы правило «что можно задать» было одно на оба входа.
- `/iters` теперь показывает и расход прогона: режим, время (прошло /
  осталось), итерации, вызовы инструментов, токены, деньги, чекпоинты и
  статус — раньше команда видела только лимит хода.
- `self_status` отдает модели раздел «Автономный прогон»: сколько раз её
  просили продолжить, было ли возобновление после обрыва, сколько
  сохранений сделано. Фильтр разделов этого инструмента тоже починен —
  он сравнивал имя раздела с префиксом заголовка и всегда возвращал
  отчёт целиком.
- `/mission report` — итоговый отчёт по прогону в markdown
  (`.gcli/mission_report.md`): цель, режим, чем остановился, таблица
  счётчиков и хроника всех событий журнала. Приложите его к задаче или PR.

**Что починено.**

- `cmdguard` перестал считать хвосты относительных путей
  («/out» из «build/out», «/...» из «go build ./...») абсолютными — на
  Linux это блокировало нормальную сборку проекта самим агентом.
- `dedupePaths` нормализует разделители явно и больше не зависит от ОС
  сборки.
- `StripJSONC` больше не сносит запятую между элементами массива — на
  ней ломался разбор mission.json с комментариями.
- Шаблон разрешений, который пишет `/init`, снова генерирует
  `bash(go build*)`, а не опасный `bash(go* build*)`.

**Инфраструктура.** GitHub Actions CI: gofmt, go vet и полный прогон
тестов на Linux и Windows при каждом пуше — проект собирается на обеих
платформах, и расхождения семантики путей теперь ловит робот, а не
человек после поломки.

## Что изменилось в 5.5.0

Релиз-исправление: найденные при параллельной работе субагентов гонки данных и
неверная классификация прерванных запусков. Новых инструментов и команд нет —
5.5.0 чинит то, что ломало работу при `spawn_agents` и Ctrl+C.

**Гонка карты прочитанных файлов.** `Base`, `Restrict` и `Merge` копировали
карту прочитанных файлов без блокировки, тогда как `read_file` писал в неё под
`readMu`. Параллельные субагенты, один из которых читал файл, а второй
создавался, давали фатальную ошибку Go `concurrent map iteration and map write`
— процесс падал целиком, без шанса на перехват. Копирование теперь идёт под той
же блокировкой (`tools/registry.go`, `snapshotRead`).

**Счётчик инструментов субагента.** Хук `OnToolStart` вызывается из горутин
параллельных запусков, а обычный счётчик терял часть вызовов, и `go test -race`
ругался на гонку. Заменён на `atomic.Int64` (`agent/subagent.go`).

**Прерванный субагент больше не считается успешным.** `Agent.Run` превращает
`context.Canceled` в `nil`, а субагент при отмене отдаёт частичный отчёт без
ошибки. Из-за этого прерванный запуск попадал в журнал как `done`, и его
выжимка уходила главному агенту как обычный результат — тот опирался на текст,
оборванный на полуслове. Теперь отмена проверяется раньше ошибки и пустого
отчёта, а статус становится `canceled` (`subagents/pool.go`).

**Отменённый отчёт не попадает в кеш.** При отмене до старта субагента `Spawn`
возвращает ошибку сразу, не занимая слот и не оставляя «полуготовый» запуск в
журнале. Прерванный результат не переиспользуется при повторе той же задачи.

**Дублирующиеся имена параллельных запусков.** Номер автоимени считался по
текущему числу запусков, а сам запуск регистрировался позже и под другой
блокировкой. Два параллельных запуска без имени получали одно и то же
`explorer-1`, и `/agents` с `agent_status` различали их только по ID. Счётчик
теперь живёт отдельно (`nameSeq`).

**Тесты.** Добавлены регрессии на каждое исправление: конкурентное копирование
карты, уникальность и последовательность имён, классификация отмены, отмена до
регистрации запуска, отсутствие кеширования отменённого результата и соблюдение
лимита параллельности под нагрузкой.

**Первая публикация.** Репозиторий выложен на GitHub: `github.com/saaae1337/gCLI`.

## Что изменилось в 5.4.0

**Продление хода.** Новый инструмент `extend_turns`. Лимит итераций больше не
стена: когда работы честно больше, чем помещается в один ход, агент может
продлить лимит, объяснив одной-двумя фразами, что осталось и почему не
помещается. Без обоснования продление не выдаётся. Продление отклоняется,
если последние ходы повторяют одни и те же вызовы (менее 30 процентов новых)
или израсходовано 90 процентов бюджета сессии. Абсолютный потолок
(`max_iters_abs`, по умолчанию 200) продление не поднимает — оно лишь
распределяет запас по требованию. За 10 итераций до лимита модель получает
предупреждение. Новая команда `/iters` показывает лимиты и журнал решений.

**Субагенты.** Автовыбор роли по тексту задачи (без `type` роль выводится
из формулировки), контракт отчёта и проверка результата, заземление выводов
на реально прочитанных файлах, кеш повторов и дедупликация одинаковых задач,
DAG-планирование пачки с `depends_on` и волнами, budget-aware маршрутизация
моделей по роли и расходу сессии (`/agents route`, `/agents budget`).

**Сборка.** Кросс-сборка пяти платформ скриптом, `SHA256SUMS.txt`, CI на
Windows, Linux и macOS с проверкой на Go 1.21 и свежей версии.

## Что изменилось в 5.3.0

**Безопасность.** Песочница файлов с корнями и запрещёнными поддеревьями,
SSRF-защита сетевых инструментов (проверка DNS-ответа и адреса),
маскирование секретов в выводе, доверие к коду проекта для навыков,
расширений и MCP.

**Инструменты.** `verify` с определением проверки по файлам проекта и
сравнением с прошлым прогоном, `project_info`, `changes`, `revert_last`,
`inspect`, `dry_run`, фоновые процессы `job`, `handoff` и `handoff_read`,
`self_status`, `ask_trace`, `task_note`, `remember`.

**Пакетный режим.** `multi_read`, `multi_edit`, `multi_grep`, `multi_bash`
одним вызовом вместо N, с живым прогрессом. `spawn_agents` — до шести
параллельных субагентов (зависимости между ними появились в 5.4.0).

**Навыки.** `load_skill` с автоподбором по описанию, `$ARGUMENTS`,
триггеры `when`.

**Интерфейс.** `Ctrl+O` работает и во время хода, и между ходами — во втором
случае показывает размышления последнего завершённого хода вместо ответа
«размышлений пока нет».

**Сборка.** Кросс-сборка пяти платформ скриптом, `SHA256SUMS.txt`, CI на
Windows, Linux и macOS с проверкой на Go 1.21 и свежей версии.
