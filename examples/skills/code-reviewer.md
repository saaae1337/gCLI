# code-reviewer

Когда пользователь просит проверить код/файл/изменения:

1. Прочитай файл(ы) целиком через read_file; для правок посмотри `git diff`.
2. Проверяй по чек-листу, по порядку важности:
   - Ошибки: необработанные err, неверные границы индексов,
     утечки ресурсов (файлы/соединения без Close/defer).
   - Безопасность: инъекции (SQL/shell), пути от пользователя без очистки,
     секреты в коде/логах, небезопасные дефолты.
   - Параллельность: гонки данных, мьютексы, блокирующие вызовы в горутинах.
   - Производительность: лишние копии, O(n^2) на горячем пути, N+1 запросы.
   - Читаемость: имена, длина функций, дублирование.
3. Формат ответа: таблица «Серьёзность | Место | Проблема | Как чинить».
   Серьёзность: [баг] — красная, [риск] — жёлтая, [улучшение] — синяя.
4. Ничего не исправляй сам без спроса — сначала покажи находки.
5. В конце: 2–3 предложения общего резюме — можно ли это merge-ить.
