# project-onboarding

Когда пользователь просит разобраться в проекте («что тут как устроено»):

1. Собери факты инструментами, не выдумывай:
   - `list_dir` в корне, затем в ключевых каталогах;
   - манифесты: go.mod / package.json / pyproject.toml / Cargo.toml / *.csproj;
   - README*.md, Makefile, docker-compose.yml, CI-конфиги (.github/workflows).
2. Построй карту: точка входа, основные модули и их роль, где конфиги,
   где тесты, как всё собирается и запускается.
3. Проверь гипотезы: запусти сборку/тесты через bash, если это безопасно
   и быстро; попробуй `--help` у сборочных скриптов.
4. Ответ структурируй: «Стек → Структура → Сборка/запуск → Точки входа →
   Подводные камни». Давай пути файлов, чтобы пользователь мог прыгнуть.
5. Предложи сохранить вывод в GCLI.md командой /init — это память проекта,
   она будет автоматически подмешиваться в будущие сессии.
