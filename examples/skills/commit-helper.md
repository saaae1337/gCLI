# commit-helper

Когда пользователь просит закоммитить изменения или написать сообщение коммита:

1. Сначала всегда посмотри состояние репозитория:
   - `git status --short` — что изменено;
   - `git diff --staged` и `git diff` — суть правок;
   - `git log --oneline -10` — стиль последних коммитов.
2. Сгруппируй изменения логически: если правки касаются разных тем,
   предложи несколько отдельных коммитов (файлы добавляй по одному:
   `git add <файл>`, не используй `git add .` без спроса).
3. Сообщение коммита — по Conventional Commits:
   `<type>(<scope>): <описание>` в инфинитиве, строчными, до 72 символов.
   Типы: feat, fix, docs, style, refactor, test, chore.
4. Никогда не выполняй `git push --force`, не трогай чужие ветки
   и не переписывай опубликованную историю без явного разрешения.
5. Перед коммитом прогони сборку/тесты проекта, если это быстро (<30 сек).
